# 🔥 Campfire

ห้องคุยเสียงแบบ peer-to-peer ที่อยู่ในไฟล์ HTML ไฟล์เดียว — ไม่ต้องติดตั้ง ไม่ต้องสมัคร ไม่มีเซิร์ฟเวอร์เก็บอะไรไว้

ก่อกองไฟ ชวนเพื่อนมานั่งล้อมวง พอคนสุดท้ายออกจากห้อง กองไฟก็ดับไปพร้อมกัน

---

## ใช้ยังไง

### แบบเร็วสุด — เปิดจากไฟล์ (คอมเท่านั้น)

1. ส่งไฟล์ `index.html` ให้เพื่อนทุกคน (Discord / LINE / อีเมล อะไรก็ได้)
2. ทุกคนดับเบิลคลิกเปิดไฟล์ในเบราว์เซอร์
3. ใส่ชื่อตัวเอง + **ชื่อห้องที่ตกลงกันไว้ให้ตรงกันเป๊ะ ๆ**
4. กด "เข้าห้อง" แล้วกด "อนุญาต" ตอนเบราว์เซอร์ขอใช้ไมค์
5. **ไมค์จะปิดไว้ก่อน** กดปุ่มไมค์หรือปุ่ม `M` เมื่อพร้อมพูด

ใครพิมพ์ชื่อห้องเหมือนกันจะเจอกัน ไม่มีระบบสมาชิกหรือรหัสผ่าน — **ชื่อห้องคือรหัสผ่านในตัว** ถ้าไม่อยากให้ใครหลงเข้ามาก็ตั้งชื่อให้เดายาก

### แบบมีลิงก์ — ต้องทำถ้าจะใช้บนมือถือ

> ⚠️ **iPhone / iPad เปิดจากไฟล์ไม่ได้** — Safari บน iOS ไม่ยอมให้เว็บที่เปิดจากไฟล์ในเครื่องใช้ไมค์ ต้องเป็นลิงก์ `https://` เท่านั้น (Android ก็เจอปัญหาคล้ายกันในบางเบราว์เซอร์)

วิธีที่เร็วที่สุด — **Netlify Drop** (~2 นาที ทำจากคอม ไม่ต้องตั้งค่าอะไร):

1. สร้างโฟลเดอร์เปล่า เอา `index.html` ใส่เข้าไปไฟล์เดียว
2. เปิด <https://app.netlify.com/drop> แล้วลากโฟลเดอร์เข้าไป
3. ได้ลิงก์ `https://xxx.netlify.app` มาทันที ส่งลิงก์นี้ให้เพื่อน เปิดได้ทุกเครื่อง

หรือถ้ามี GitHub อยู่แล้ว — **GitHub Pages**:

1. สร้าง repo สาธารณะ อัป `index.html` เข้าไป
2. Settings → Pages → Branch `main` → Save
3. รอสักครู่ จะได้ `https://<user>.github.io/<repo>/`

> โฮสต์อะไรก็ได้ที่เสิร์ฟเป็น HTTPS — ไม่ต้องมี backend เพราะทั้งแอปคือไฟล์ static ไฟล์เดียว

## มีอะไรบ้าง

| ฟีเจอร์ | รายละเอียด |
|---|---|
| เปิด/ปิดไมค์ | ปุ่มกลาง หรือกด `M` — ปิดที่ตัว audio track จริง ไม่ใช่แค่ไอคอน |
| ปิดเสียงทุกคน | ปุ่มลำโพง หรือกด `D` |
| เห็นว่าใครพูด | ขอบการ์ดและวงรอบตัวอักษรเรืองแสงสีไฟตามเสียงจริง (วิเคราะห์ในเครื่อง ไม่ได้ส่งข้อมูลอะไรเพิ่ม) |
| ปรับเสียงรายคน | สไลเดอร์ข้างชื่อแต่ละคน ปรับเฉพาะที่เครื่องเรา |
| ตัดเสียงรบกวน | Noise gate ปิดไมค์อัตโนมัติตอนไม่ได้พูด พร้อมมิเตอร์และสไลเดอร์ปรับความไว (ดูหัวข้อด้านล่าง) |
| เลือกไมค์ | สลับไมค์/หูฟังได้กลางคันโดยไม่ต้องออกห้อง จำค่าที่เลือกไว้ให้ครั้งหน้า |
| เจ้าของห้องหลุด | คนที่เหลือรับช่วงต่ออัตโนมัติใน ~10 วินาที เสียงที่กำลังคุยอยู่ไม่ขาด |

**ปุ่มลัด:** `M` เปิด/ปิดไมค์ · `D` ปิดเสียงทุกคน

**เหมาะกับ 2–6 คน** — เสียงวิ่งแบบ full mesh (ทุกคนต่อตรงหากันหมด) ยิ่งคนเยอะยิ่งกินแบนด์วิดท์ขาขึ้นแบบทวีคูณ

## ทำงานยังไง

### ภาพรวม

```
              ┌──────────────────────┐
              │   0.peerjs.com       │  ← แค่พาสองเครื่องมาเจอกันตอนแรก
              │   (signaling)        │     ไม่มีเสียงวิ่งผ่านตรงนี้
              └──────────────────────┘
                   ▲     ▲     ▲
                   │     │     │   (WebSocket ตอน handshake เท่านั้น)
              ┌────┴─┐ ┌─┴───┐ ┌┴────┐
              │  A   │◄┤  B  ├►│  C  │
              └──┬───┘ └─────┘ └───┬─┘
                 └─────────────────┘
                   เสียงวิ่งตรงระหว่างเครื่อง (WebRTC)
```

เสียงไม่เคยผ่านเซิร์ฟเวอร์ใคร เซิร์ฟเวอร์ signaling มีหน้าที่แค่แลก SDP/ICE ตอนเริ่มต้นเท่านั้น

### ชื่อห้อง → peer id

ชื่อห้องถูก slug + hash (djb2) เป็น id คงที่ เช่น `microom-v1-kuan-game-1x9k2p`

- **เจ้าของห้อง (host)** คือคนที่จองชื่อ id นั้นบนเซิร์ฟเวอร์ signaling ได้ — ใครเข้ามาก่อนได้เป็น
- **คนอื่น ๆ** ใช้ id แบบ `microom-v1-kuan-game-1x9k2p-u<สุ่ม>` แล้วต่อ data connection ไปหา host

host ทำหน้าที่เป็น **สมุดรายชื่อ** อย่างเดียว ไม่ได้เป็นตัวกลางส่งเสียง — พอรู้รายชื่อกันแล้วทุกคนโทรหากันเองตรง ๆ

### กติกาที่ทำให้ไม่ต่อซ้ำซ้อน

ทุกคู่จะมี media connection เดียว โดยให้ **ฝั่งที่ peer id เรียงน้อยกว่าเป็นคนโทรออก** อีกฝั่งรอรับอย่างเดียว

### Heartbeat & การรับช่วงต่อ

- host broadcast รายชื่อทุก **3 วินาที**
- สมาชิกส่ง ping กลับทุก 3 วินาที — host ตัดคนที่เงียบเกิน **12 วินาที** ออกจากรายชื่อ
- ถ้าสมาชิกไม่ได้ยินจาก host เกิน **11 วินาที** ถือว่า host หายไป แล้วแย่งกันจอง id ห้องใหม่ด้วย random backoff (0.8–3 วินาที) — คนที่ชนะกลายเป็น host คนใหม่ ที่เหลือต่อกลับเข้ามาเอง
- media connection ที่ตายแล้ว (`connectionState` เป็น `failed`/`closed`) ถูกเก็บกวาดทุกรอบ heartbeat

ระหว่างเปลี่ยนมือ **เสียงที่ต่ออยู่แล้วไม่ขาด** เพราะ WebRTC connection เป็นอิสระจาก signaling

### ตัดเสียงรบกวน

มีสองชั้นซ้อนกัน

**ชั้นแรก — DSP ของเบราว์เซอร์** เปิดไว้ตลอดตอนขอใช้ไมค์:

```js
{ echoCancellation: true, noiseSuppression: true, autoGainControl: true }
```

จัดการเสียงที่ดังต่อเนื่องคงที่ (พัดลม แอร์ เสียงซ่า) กันเสียงวนจากลำโพง และปรับความดังให้สม่ำเสมอ

**ชั้นสอง — Noise gate** เขียนเองด้วย Web Audio เพื่อตัดสิ่งที่ชั้นแรกทำไม่ได้ คือเสียงเป็นจังหวะอย่างคีย์บอร์ดหรือเสียงคนข้าง ๆ **ในช่วงที่เราไม่ได้พูด**

```
ไมค์ ──┬──► AnalyserNode ──► วัดระดับเสียง (ก่อนถูกตัด)
       │
       └──► GainNode (ประตู) ──► MediaStreamDestination ──► ส่งออกให้เพื่อน
```

- วัดระดับจาก**ก่อน**ประตู เพื่อให้ยังรู้ว่าเริ่มพูดแล้วแม้ประตูกำลังปิดอยู่
- เกินเกณฑ์ → เปิดประตู ramp 10 ms (เร็วพอที่จะไม่กินคำแรก)
- เงียบลง → ค้างเปิดไว้อีก 350 ms แล้วค่อยปิดแบบ ramp 120 ms (ไม่กินคำท้ายประโยค ไม่มีเสียงกึก)
- ปิดไมค์ = สั่ง `enabled = false` ทั้งฝั่งดิบและฝั่งที่ส่งออก ไม่ได้พึ่งประตูอย่างเดียว

ผลพลอยได้: track ที่ส่งออกคือปลายทางของสาย ไม่ใช่ track ของไมค์โดยตรง เลย**สลับไมค์กลางคันได้โดยไม่ต้อง renegotiate** กับใครเลย — แค่ต่อต้นทางใหม่เข้าสายเดิม

ถ้าเบราว์เซอร์ทำ Web Audio ไม่ได้ จะถอยไปส่งเสียงดิบตรง ๆ แทน (แล้วค่อยใช้ `replaceTrack` ตอนสลับไมค์)

## โครงสร้างไฟล์

```
index.html   แอปทั้งตัว — HTML + CSS + JS + PeerJS ฝังมาในไฟล์เดียว
README.md    ไฟล์นี้
```

ไม่มี build step ไม่มี dependency ให้ติดตั้ง แก้ไฟล์แล้วรีเฟรชได้เลย

**ข้อมูลที่เก็บใน localStorage:** `mr_name` (ชื่อ), `mr_room` (ห้องล่าสุด), `mr_mic` (ไมค์ที่เลือก), `mr_gate` + `mr_gate_th` (การตั้งค่า noise gate) — เก็บในเครื่องตัวเองล้วน ๆ ไม่ได้ส่งไปไหน

## ข้อจำกัดที่รู้อยู่

- **iOS ต้องเปิดผ่าน HTTPS** เท่านั้น (ดูหัวข้อด้านบน)
- **พึ่งเซิร์ฟเวอร์ signaling สาธารณะ** — `0.peerjs.com` เป็นบริการฟรีที่ไม่มีใครรับประกัน ถ้าล่มก็เข้าห้องใหม่ไม่ได้ (ห้องที่ต่อกันอยู่แล้วยังคุยได้ต่อ) ถ้าจะใช้จริงจังควร self-host PeerServer
- **ไม่มีการเข้ารหัสระดับแอป** — WebRTC เข้ารหัส DTLS-SRTP ให้อยู่แล้วระหว่างทาง แต่ใครรู้ชื่อห้องก็เข้ามาได้
- **TURN สาธารณะไม่การันตี** — ถ้า openrelay ล่มและเน็ตทั้งสองฝั่งเป็น NAT โหด อาจต่อกันไม่ติด
- **ยังไม่ได้ทดสอบกับเซิร์ฟเวอร์ signaling ตัวจริง** — logic ทั้งหมด (mesh 3 เครื่อง, การรับช่วงต่อ, สถานะไมค์) ทดสอบผ่านด้วย PeerServer ที่รันในเครื่อง
